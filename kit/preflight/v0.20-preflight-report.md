## Design choices after the test

| Need | Treatment after preflight |
|---|---|
| Package the agent | Hermes profile distribution plus external security/pinning policy where required |
| Hold the mission and done criteria | Hermes goal/completion contract, with deterministic/checker/human disposition outside the goal judge |
| Coordinate multiple roles | Hermes Kanban board/profile workers, without audit-log or hard tenant-isolation claims |
| Gate risky commands | Hermes approvals/deny rules plus OS/container isolation and organization authority policy |
| Protect sandbox credentials/egress | Iron Proxy on supported Docker topology plus separately verified isolation |
| Hide runtime choices from ordinary user | Evaluation Kit policy resolver selecting a preapproved configuration bundle |
| Prove/check work | Deterministic oracle + separately controlled checker + human disposition |
| Assemble/custody evidence | Evaluation Kit B09 packet; mutable until an external evidence store is adopted |
| Measure cost | B10 only after explicit auth/spend authority |

## Decision

No mandatory reference-path primitive returned `FAIL`. v0.20 remains the pin and the v0.19 fallback is not triggered.

`PASS_WITH_LIMITS` is intentional: the release is capable enough to build on, but the product must expose its boundaries. B01 is unblocked. B05 may proceed after its B02/B17 design dependencies close. B07 must produce its own end-to-end evidence rather than inherit the preflight verdict.
